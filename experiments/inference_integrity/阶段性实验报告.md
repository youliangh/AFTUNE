## 方法与判定边界

实验依据[实验蓝图](../../experiment-blueprint.md)和[完整实验方案](实验方案.md)。[Jin 等的论文](../../usenixsecurity26-jin.pdf) §5.1、§5.5、§5.7–5.8 讨论给定可信参数、输入与输出时的前向计算验证、块记录和承诺后抽样。本实验将现有 AFTUNE `Recorder`/`verify_inference` 应用于自回归生成的记录，分别考察生成现场 **D**、事后干净重算 **R**；它们是同一请求的配对证据，不算作独立请求。

每个正式条件有 256 条请求，固定 32 条阳性、224 条阴性；Llama 工作负载的 prompt 为 32 tokens、总长 128 tokens。仅运行 **seed 0**，不重复随机种子。另有 **32 条独立正常校准请求**，按源行、文本哈希和 token IDs 均与正式请求不重叠。生成和验证均为 `cuda:0`、FP32、SDPA；D、R、Model 三个证据来源各自冻结的数值阈值均为 **0.0**。数值模式以块分数超阈值或输入/磁盘完整性错误拒绝；严格模式另拒绝计算输出哈希不一致。

表中四格顺序为 **TP/FN/FP/TN**。TPR、FPR 的区间是以请求为单位的 95% Wilson 区间，不能解释为跨模型、跨种子或跨工作负载的不确定性。所有已完成五个条件的 32 个阳性注入均成功，所有证据无执行错误或不可判定结果。

## 当前可支持的解释与限制

- KV、Serving r6 和 Computation 的生成现场 D 各检出 32/32 阳性；其事后干净重算 R 各漏检 32/32。后者的通过仅说明提交的重算 forward 自洽，不能证明先前的生成过程没有违例。
- Model Mismatch 只给验证器**声明 Llama 的现场重算记录**，没有把 Qwen 的生成轨迹交给它；32/32 阳性均通过此单一证据条件。Qwen 源序列实际总长为 127 或 128；文本桥接后的 Llama 序列为 121–128，这一跨 tokenizer 例外不能宣称两种架构均严格满足总长 128。
- Token Selection 的 32/32 阳性在 D/R 均通过，符合现有块检查不验证 logits 到返回 token 的规则这一接口边界。Input 的部分观察也与验证器只读取交换后的实际输入、未获独立原请求锚一致；完整结论仍待剩余 200 例。
- KV 使用完整前缀的 context 替换模拟，未改变物理 `DynamicCache`；Serving 使用持续的 FP32 舍入代理，未实测设备路由或 thinking budget；Computation 是激活扰动，并非真实 CUDA kernel 故障。GPU 重算未提供 TEE 远程认证或失陷宿主机隔离保证。本轮单 seed、小模型、短输入的结果不直接外推到其他部署。

最终交付仍需 Input、Serving r2/r10 全部完成，完成审计核对 2,048 案例和 15 个证据组后生成正式报告。
