# AFTUNE 推理完整性违例评估方案

本文描述修订后的 `formal-seed0-cal32-v3` 实验协议，不包含正式实验结果。实验以仓库的实验蓝图为基础，评估现有 AFTUNE 检查能够发现哪些模拟违例，以及提交的计算证据是否足以证明实际生成遵守请求契约。适配层已加入两层块、稀疏激活准备和共享阴性对照池；正式运行前须通过独立目录中的完整长度 GPU→CPU 预检。

## 1. 论文背景与被测边界

论文 §5.1 将推理验证表述为：给定可信模型参数、输入和声明输出，验证输出来自该模型的完整前向计算。§5.5 将一次 inference request 视作一个 step，固定 `B_S=1`，记录并重算层块边界激活；§5.7–5.8 采用提交承诺后抽样的审计方式。artifact 的 `inference.py` 同样固定 `steps_per_block=1`，推理实验不将 `B_S` 作为调参项，也不跨请求分组。上述论文内容分别见本地 PDF 第 6、8、9 页；PDF 包含一页封面。论文 §6.4.1 在 PDF 第 13–14 页讨论 BF16 数值容差的攻击空间，并将 FP32 作为推理验证最低精度。

论文的这些声明不等于已经明确验证了自回归生成的每次选词、KV 历史、设备路由或思考预算。本实验把自回归过程中的每次完整前缀 forward 映射为一份原生推理记录，由适配层编排 96 次记录；这不表示论文原生流程端到端覆盖了 96 次选词。本实验区分两个问题：提交的 forward 记录是否计算一致，以及这份记录是否足以证明实际生成遵守了请求契约。

被测主体为现有 `Recorder` 和 `verify_inference` 的记录、哈希与重算检查。实验适配层负责精确 token 输入、多步编排、注入、结果保存和阈值判定；没有新增 token 选择、原始请求身份、缓存历史或设备路由检测器。声明模型为本地 Llama-3.2-1B-Instruct，检查范围是 embedding、16 个 decoder layers 和 norm，共 18 个跟踪模块。设置 `B_L=2`，按 Recorder 的模块顺序两两分组，共 9 个层块：首块为 `embedding + layer_0`，中间依次为 `layer_1 + layer_2` 至 `layer_13 + layer_14`，末块为 `layer_15 + norm`。`lm_head` 和 logits 到返回 token 的关系不在现有检查范围内。验证使用由本地已哈希锁定的声明模型 checkpoint 加载并导出的参考快照；快照哈希只能核验其后续未被改动，不能单独证明权重来源或 TEE 信任。

设置 `I_A=4`，含义为每隔 4 个层块保存边界激活张量：按从 0 开始的编号，常规保存块 0、4、8 的输出，其余层块仍提交输出哈希。该间隔不作用于 decode step，也不把检查总体缩减为 3 个块。验证所需的缺失边界张量经激活准备阶段补齐：适配层在真实前向时暂存原始边界输出，在稀疏基础记录落盘并冻结其文件哈希后揭示这些原始张量，核验生成时已提交的输出哈希。该路径保留实际注入值，不用干净重算替换，也不改写原承诺。全量检查需要揭示全部缺失边界，最终证据大小包括补齐张量，不能作为仅保存稀疏激活时的存储成本；基础记录与补齐成本分别保存在 `activation_preparation.json`。正式运行前必须验证两层块与稀疏激活路径可用；无法补齐的证据按第 4 节记录错误。

## 2. 固定工作负载与证据条件

正式实验只有一个 seed：`0`。先冻结同一组 256 个正式输入，以无放回均匀抽样确定恰好 32 个阳性输入索引，其余 224 个作为所有 violation 类型共享的无 violation 样本。每类实验在相同的 32 个阳性输入上分别注入一次违例，并引用同一批 224 个阴性样本，因此每类的统计视图仍为 `M=256`、`N=32`。另选 32 个与全部正式输入不重叠的正常请求用于校准，不参与测试指标。

共享阴性池中，每个输入仅由 Llama 干净生成一次，复用其输入、生成 token IDs 和响应文本。生成时记录 D 证据；再将同一响应文本按 Model 条件的文本桥接流程重分词，由声明 Llama 重算并记录 Model 证据。每份证据只做一次 CPU 验证，并生成一套抽样结果。五类非 Model 实验共同引用 D，Model Mismatch 引用 Model 证据；共享不限于输入索引，还包括生成结果、证据、验证判定和抽样结果。

数据来自 `ShenLab/MentalChat16K` 的固定 revision `5f60cd380cfc58f0f12d44892bed41ee3670a70a`，只使用 `input` 字段。按 Llama tokenizer 过滤过短文本，构造一个 BOS 加前 31 个内容 token，按最终 32-token 输入去重后抽样。不套用 chat template。Llama 请求 `P=32`，屏蔽 EOS 后贪心生成 96 tokens，其原始生成序列总长 `max_length=128`；Model 条件经过文本桥接后的证据长度另见下文。

生成和证据记录使用 GPU `cuda:0`，包括 Model 条件中声明 Llama 的桥接序列重算；验证器在 CPU 上加载可信参考模块并重算审计，配置为 `generation_device="cuda:0"`、`verification_device="cpu"`。两侧均使用 FP32、SDPA、batch size 1；模型处于 eval 模式，所有 forward 都使用 `use_cache=False`。固定 Python、NumPy、PyTorch 随机状态，要求确定性算法，关闭 TF32 和 cuDNN benchmarking，固定 cuBLAS workspace 配置。GPU 生成、CPU 验证是所有条件的正常实验配置，不作为 Serving 注入；GPU 到 CPU 的正常数值差异由本协议重新校准。

| 证据条件 | 产生方式 | 每个请求的检查数量 | 回答的问题 |
|---|---|---:|---|
| D：`generation_live` | 每次选 token 前，对当时真实执行的完整前缀 forward 同步记录，阳性的注入 hook 在记录时有效 | 96 × 9 = 864 | 生成过程中已记录的局部计算是否一致 |
| Model：`model_recompute_live` | 源模型生成文本，经 Llama 重分词后，由 Llama 在 GPU 上实际重算并同步记录 | 9 | 声明模型的有效重算证明是否绑定真实生成模型 |

五类非 Model 条件的阳性仅产生 D 证据，Model 条件的阳性仅产生 Model 证据。Model 阳性由 Qwen3.5-0.8B 生成，阴性复用共享池中的 Llama 响应文本；两者执行相同的文本桥接、Llama 重分词及重算流程。验证 Model 时只提供 `model_recompute_live`，不向验证器附带共享池的 D 生成 trace 或来源 oracle。

跨模型桥接保留相同的截断请求文本，但 Qwen 独立分词，源 prompt 长度不强制为 32。源模型生成 96 个源 tokenizer tokens，其响应文本由 Llama 重新分词后接到原始 32-token Llama prompt 后。实现不截断或补齐桥接结果，因此 Model 证据长度可以超过或少于 128；必须保留实际长度，不声称跨 tokenizer 同时满足固定 token 数。重算输入均去掉桥接序列最后一个 token，且现有验证器不检查下一 token 是否确为实际返回 token。

这是对蓝图 `P=32/max_length=128` 的显式跨 tokenizer 例外。旧版冻结语料的长度诊断为：Qwen 对同一请求文本的输入长度为 31 的有 242 条、为 32 的有 14 条；32 个 Model 阳性分别为 31 条和 1 条，所以源序列总长为 127 或 128。旧版完整长度诊断 gate 中，Model 阳性源长 127、阴性源长 128，二者桥接总长恰好都是 128。这些是历史诊断，不是修订协议的正式结果；修订运行须重新保存逐请求实际长度。保留同一请求文本与“源生成→文本桥接→Llama 实时重算”的可见性边界，不添加或删除 token 来强制两种词表计数相等。该协议可评估相同文本下的生成来源完整性，不能称为对所有模型严格等 token 长度的复现。

共运行六个主条件，每个条件只对应一种证据来源，共 6 个条件/证据组。正式规模按实际执行、证据记录和统计引用分别报告：

| 统计对象 | 数量 |
|---|---:|
| 正式输入 | 224 个共享阴性输入 + 32 个共同阳性输入 = 256 |
| 每类实验的统计视图 | 32 个阳性 + 224 个共享阴性 = 256 |
| 正式目标生成任务 | 224 次共享干净生成 + 6 × 32 次阳性生成 = 416 |
| 去重后的 D 序列级证据记录 | 224 个共享阴性 + 5 × 32 个阳性 = 384 |
| 去重后的 Model 序列级证据记录 | 224 个共享阴性 + 32 个阳性 = 256 |
| 去重后的序列级证据记录合计 | 224 × 2 + 6 × 32 = 640 |
| 六类实验的样本引用次数 | 6 × 256 = 1,536 |

416 个目标生成任务和 640 条证据记录不含校准、KV donor 辅助执行及失败重试；Model 的声明 Llama 证明重算也不另计为源生成任务，其执行成本单列。1,536 次引用不是独立样本，640 条证据也不是统计独立样本：共享阴性的 D 与 Model 来自同一次生成，六类阳性复用相同输入。D、Model 使用同一组 32 个独立正常校准请求，各自产生对应证据并冻结阈值；正式共享阴性不得用于调阈值。

## 3. 注入与独立真值

“一次违例”按一次外生事件定义：KV、Computation、Token Selection 只在一个 decode step 触发；Input、Model 在请求级触发；Serving 只发生一次切换，其后效应持续。decode 注入 step 从 2–96 均匀选取；KV 和 Computation 的 decoder layer 从 0–15 均匀选取。注入位置与方向由独立派生种子确定。

| 主条件 | 注入机制 | 成功判据与保存的真值 |
|---|---|---|
| KV Cache Mismatch：`kv_cache` | 选相邻请求作为干净 donor，独立生成等长前缀；在目标层捕获 donor 的真实归一化 attention 输入并计算含 RoPE 的 K 和 V。替换一个历史位置供当前最后一个 query 使用，以原完整前缀形状及 attention backend 重算，只替换最后一行 attention 输出 | 目标 attention 仅触发一次，K/V 历史槽确实不同；保存请求/实际槽位、K/V 前后哈希、输出差异范数。若初选槽相同，按固定循环顺序找首个不同历史槽；不存在则报错 |
| Serving Configuration：`serving_config` | 从指定 step 起，对每个 decoder layer 的末位 MLP 输出执行 FP32 尾数低 6 位的 nearest-even 舍入，dtype 和指数范围不变，持续到请求结束 | 恰好一次 `route_switch` 事件，之后每步全部层执行 hook，至少一个激活元素改变；保存每步每层变化与舍入位数 |
| Model Mismatch：`model_mismatch` | 请求级将源生成模型替换为 Qwen，再按上述文本桥接进入声明 Llama 的实时重算记录 | Qwen 成功加载并完成生成，存在唯一模型替换事件；保留源模型路径、源 token IDs/文本和 Llama 重分词 IDs。是否恰好产生相同文本不影响违例标签 |
| Token Selection Mismatch：`token_selection` | 在一次选词时，将正常 greedy token 换成得分最高的另一合法、非特殊 token，后续继续正常生成 | 存在唯一事件且替换 token 不同；记录正常/替换 ID、对应 logit 和 step |
| Computation Mismatch：`computation` | 一步一层的末位 MLP 输出加上随机正负方向扰动，方向归一化，目标相对 L2 幅度为 `1e-2`，之后正常执行 | hook 恰好触发一次且元素有变化；保存前后哈希、原向量/差值 L2、变化元素数。模拟计算结果错误，不宣称实际破坏了 CUDA kernel |
| Input Mismatch：`input_mismatch` | prefill 前交换两个内容不同、互不重叠的四-token 段，保留 BOS 和 32-token 总长度 | 唯一交换事件；保存原始/实际输入、段起点和宽度。此版本评估重排序，不覆盖删除子型 |

Serving 只运行 `serving_config` 的 r6 配置，即舍入 FP32 尾数低 6 位，不做强度扫描。它模拟配置变化造成的数值后果，并非真实迁移到不同物理设备；没有实现 thinking-budget 子型。

注入成功依据独立事件和实际状态变化判定，不依赖工具是否检出，也不要求最终文本改变。私有 `oracle/` 保存源请求、模型身份、生成过程、donor 信息与事件；验证器不读取这些文件。尤其 Input 条件中，现有验证器读取记录内的实际输入，未获得独立客户端原始输入锚；该限制是被测接口的边界。

## 4. 判定、统计与采样

数值主模式沿用原生块分数：记录输出 L2 非零时，用重算输出与记录输出的差值 L2，除以记录输出 L2 加 `1e-10`；记录输出范数为零时，原生实现直接返回分数 0。每条证据的分数是全部受支持块分数的最大值；D 的最大值同时跨 96 个 forward。块分数覆盖记录张量的全部 token，因此仅末位的扰动可能被前缀总体范数稀释；零范数分支也可能漏掉差异。

分别对 D、Model，以对应 32 个正常校准请求的序列分数最大值设定阈值 τ，并在正式运行前冻结。校准必须使用本轮 GPU 生成、CPU 验证及 `B_L=2`、`I_A=4` 的配置，不能复用旧版 GPU 验证阈值。任一块分数严格大于 τ 则拒绝。校准中缺失记录、非有限分数或错误均阻止产生正式阈值；不根据攻击结果或正式共享阴性调参。该最大值阈值保证校准集内无数值误报，不保证未知分布或其他设备上零误报。

数值主模式中，显式输入/磁盘哈希不匹配或数值超阈值作为 `DETECTED`；成功完成全部检查且未超阈值为 `PASSED`；其他执行故障、缺失证据、无法补齐的激活或无效分数为 `ERROR`。仅计算输出哈希不同而数值未超阈值，不触发数值主模式拒绝。已有明确拒绝同时存在其他错误时，序列仍记 `DETECTED`，并保留错误详情。另报告严格输出哈希模式：它利用同一次重算已计算的哈希结果，将计算输出哈希不匹配也判为拒绝，检验位级一致性，不使用数值阈值。GPU 与 CPU 的正常 FP32 数值差异也可能造成计算输出哈希不同，因此严格模式的拒绝不单独证明发生违例，须结合正常对照的误报情况解释，不能与数值主模式混合统计。

对注入成功且可判定的阳性，`DETECTED/PASSED` 分别计 TP/FN；正常请求分别计 FP/TN。按条件、证据来源及判定模式输出四格原始计数，并报告 TPR、FPR、precision、F1，以及 TPR/FPR 的 95% Wilson 区间。未定义分母输出空值。注入失败和注入状态未知单列；错误与不支持结果不塞入四格。另报告注入成功率、可判定覆盖率及 `deployment_recall = TP / 全部成功注入阳性`，避免只展示成功完成审计的样本。

每类条件的 TP/FN 来自自身 32 个阳性，FP/TN 来自对应证据来源的 224 个共享阴性。五类 D 条件复用相同的阴性判定与抽样结果，其 FP/TN、FPR 和阴性错误数量应一致；Model 使用同一批生成样本的 Model 证据判定，不混用 D 的结果。同一共享证据的错误及重试后的有效版本须同步用于所有引用条件。每类 FPR 区间的阴性分母最多为 224；跨条件不重复累计这些阴性，也不通过 1,536 次引用扩大区间样本量。共享输入带来的条件间相关性须在结果解释中保留。

首先全量检查，再从冻结的块结果中无放回抽样，评估审计预算。采样率仅为 `p=8%`，每条去重后的证据执行一套 1,000 次抽样；抽取数 `s=max(1,ceil(pB))`，上限 B。D 的抽样总体是 96 个 forward × 9 个层块，共 864 个单元，每轮抽 `ceil(0.08 × 864)=70` 个；Model 的总体是 9 个块，每轮抽 `ceil(0.08 × 9)=1` 个。采样率向上取整后，实际抽取比例分别为约 8.10% 和 11.11%；同一名义采样率不代表相同审计成本。

采样种子在证据文件承诺后生成并保存。每次抽样由唯一源证据标识、采样率、重复编号和该种子确定，保存首轮明确索引及完整重建规则。共享阴性以样本标识和证据来源确定唯一源证据标识，不将引用它的 violation 类型加入抽样键；所有引用条件复用同一套种子、索引与判定，不重新抽样。阳性证据标识包含其 violation 类型，以区分各自注入记录。设固定结果中有 k 个被拒绝块，理论命中概率为：

\[
P_{\mathrm{hit}}=1-\frac{\binom{B-k}{s}}{\binom{B}{s}}.
\]

同时输出模拟命中率、理论概率、采样 TP/FN/FP/TN 与错误数量。k 是违反被检验局部关系的块数，不能用“相对正常运行数值改变的块数”替代。若事后重算自洽使 k=0，提高采样率仍无法发现未进入证据的生成历史违例。每条请求的 1,000 次重复不是 1,000 个独立请求，不据此扩大 Wilson 区间样本量；采样复用已完成的重算结果，也不作为真实多次 TEE 调用的性能测量。

## 5. 运行、可复现性与解释限制

修订协议采用独立版本 `formal-seed0-cal32-v3`，结果隔离到工作区 `.cache/experiment-runs/aftune-inference-integrity-seed0-cal32-v3`。默认配置为 `formal-seed0-cal32-v3.json`，旧版配置和结果不并入本轮。正式执行须校验以下配置与行为生效：

- 参考快照与记录端一致使用 `B_L=2`、`I_A=4`，完成稀疏激活准备及原始承诺核验，验证端实际在 CPU 重算。
- 仅保留 D、Model 两种证据来源及六个主条件，Serving 固定 r6，采样率固定 8%。
- 建立 224 个样本的共享阴性池，各类型通过唯一源证据标识引用验证和抽样结果；摘要、完整性审计和断点恢复均识别共享关系。
- 通过正常与注入样本的预检，重新冻结本轮 D、Model 阈值，使用显式修订配置和独立输出目录。

从 `AFTUNE` 目录按 `fetch → prepare → calibrate → run → summarize` 顺序执行。`run` 先完成共享阴性池的生成与两种证据验证，再运行六类各 32 个阳性；各条件的阴性统计直接引用共享池。正式摘要须检查全部 640 条去重证据及六个 256 样本统计视图完整存在。使用 `.venv/bin/python -m experiments.inference_integrity.supervise --output ../.cache/experiment-runs/aftune-inference-integrity-seed0-cal32-v3 --interval 60` 执行完整流程；监督器以独占锁避免同目录重复运行，每 60 秒保存进程、阶段、数量、错误、磁盘及 GPU 状态，完成后重建抽样结果并审计，审计通过后生成结果报告。`runner_state.json` 保存阶段和终止状态，`monitor.jsonl` 保存连续状态快照。

`fetch` 显式获取并验证固定数据；之后的阶段只读本地冻结数据。`prepare` 校验数据行数/哈希，保存抽样语料、配置和环境信息。`manifest.json` 记录数据源文件及派生 JSONL、模型 safetensors/索引、config/tokenizer 文件与核心实验/验证文件的 SHA-256，并记录共享阴性样本、证据及条件引用映射；`reference/ready.json` 单独保存参考快照各文件的哈希。恢复运行时检查配置、语料、数据、模型、参考快照、核心代码及引用映射是否变化；变更应使用独立输出目录。修订协议的正式报告只使用 v3，旧诊断目录和旧阈值不并入结果。

每个实际生成任务保留 oracle；每份源证据保留提交文件的哈希、逐块数值/严格哈希结果、抽样记录和序列判定。共享阴性池集中保存上述记录及其有效版本，条件视图引用同一份记录。预先指定索引 0、64、128、192 保留完整张量，其余请求在审计后释放临时记录；共享阴性保留其 D、Model 两种证据，阳性保留各自条件对应的证据。保留的原始分数支持重算统计；要重新执行未保留请求的底层重算，需要按冻结配置重新生成。GPU 生成、证据记录、激活准备、Model 桥接重算、CPU 验证和存储分别保存实际成本；校准、KV donor 和失败重试单列。跨条件汇总时，共享阴性的生成、证据、验证、抽样和存储均只计一次，不按引用次数重复相加。

断点恢复按源证据标识跳过已完成任务；错误重试先归档旧证据。共享记录的错误、可判定状态和重试版本一致传播到全部引用条件，不得只替换某一条件的阴性结果。连续三次相同错误、磁盘不足 5 GiB、GPU 不可用、可用显存不足 768 MiB 或 GPU OOM 会停止进一步运行以便诊断；CPU 验证故障按相同错误口径保存并处理。`summarize --partial` 只生成明确标识未完成的诊断摘要；正式摘要要求所有计划证据及共享引用完整且一致。

解释结果时保留以下边界：这是一轮固定 seed、小模型和固定短输入的机制评估，置信区间不覆盖跨 seed、模型、工作负载的外推不确定性；共享阴性及共同阳性输入使各类型的统计相关，不能视为六批独立实验样本；KV 是完整前缀 context 替换模拟，未测试物理 DynamicCache 的复用/迁移生命周期；Serving 是人工舍入代理，未证明设备身份或思考预算；GPU 记录、CPU 上基于本地哈希锁定参考快照的重算只测试验证逻辑，未独立建立 checkpoint 来源信任，也未执行 TEE 远程认证或验证宿主机失陷下的隔离保证。Model 阳性在 Llama 重算通过时，应记为“生成来源完整性”的漏检，同时说明该重算 trace 本身仍可能计算正确。所有检出率须由完整正式结果计算，不能由上述预期边界代替测量。
