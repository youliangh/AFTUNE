# Qwen3.5-0.8B 推理完整性实验方案（v4）

声明及可信参考模型为本地 Qwen3.5-0.8B；Model Mismatch 替代源为本地 Llama-3.2-1B-Instruct。仅使用文本模型，不新增 lm_head、选词关系、原始客户端输入、路由身份或 TEE 认证检查。旧 v3 代码与结果原样保留。

## 固定协议与配对输入

seed 0，FP32、eval、batch size 1、`use_cache=False`；GPU cuda:0 生成并记录，CPU 8 线程验证。Full attention 使用 SDPA；18个 linear-attention 层使用当前纯 Torch fallback，冻结其可选 kernel 可用性和实现源文件哈希。

加载时显式设置文本子配置及参数的FP32精度，并在参考导出和每个录制边界检查实际dtype。首轮诊断发现的嵌套配置BF16默认值问题单独保留，修复后重新预检，其失败分数不进入正式校准。

复用 v3 的32个校准数据行、256个正式数据行、32个阳性索引及原索引次序。原始数据固定为 MentalChat16K revision `5f60cd380cfc58f0f12d44892bed41ee3670a70a` 的 input 字段。从每条原始文本取 Qwen 前32个内容 token，不添加 BOS 或 chat template，请求文本解码全部32个token。已只读核实288个前缀唯一、足够长且校准/正式不重叠。源文本、请求文本、token IDs和引用运行均保存哈希；不依据旧结果选择样本。

声明Qwen固定生成96个token，原始序列总长128。普通greedy仅屏蔽 tokenizer EOS（Qwen 248046，Llama 128009）及无词表对应ID。Qwen head的248320行中，合法词表ID当前为0–248076，其余243行屏蔽。Qwen config EOS/PAD 248044不额外屏蔽于普通greedy；Token Selection替换额外排除全部special。实际合法集合、EOS/PAD/BOS及后端写入manifest。

六类实验在相同32个阳性输入上分别注入；其余224个输入由Qwen各干净生成一次，并产生D和Model证据，各验证一次、各抽样一次。五类非Model条件共享D，Model条件引用同一响应来源的Model证据。所有生成、阈值、证据和抽样结果均重新计算。

## 记录、证据与抽样

`B_L=2`、`I_A=4`、原生inference `B_S=1`。Embedding＋24 decoder＋norm共26模块、13块：首块embedding+layer0，中间两两分组，末块layer23+norm。稀疏基础保存块0/4/8/12，其余9个原始真实前向输出在基础文件冻结后揭示并检查原输出哈希；保留实际注入值，不用干净重算替换。最终证据成本包含补齐成本。

| 证据 | 产生方式 | 全量单元 | 每轮8%抽样 |
|---|---|---:|---:|
| D：generation_live | 96次真实生成前缀forward同步记录 | 1248 | 100，实际8.0128% |
| Model：model_recompute_live | 源响应文本桥接后，由Qwen GPU实时重算 | 13 | 2，实际15.3846% |

每份去重证据在文件承诺后生成新审计种子，先全量验证再无放回模拟1000次。共享阴性的源证据键不含引用条件，不重新抽样。保存首轮索引、源种子、挑战时间和完整重建规则，报告理论与模拟命中率；重复和共享引用不扩大独立样本量。

Model阳性：Llama独立分词相同请求文本，源prompt长度不限为32，生成96个Llama tokens；响应文本经Qwen tokenizer重分词后接到原32-token Qwen prompt，Qwen GPU对 `bridged_ids[:-1]` 实际重算，CPU仅验证Model证据。共享阴性使用Qwen响应走相同桥接。逐请求保留源和桥接实际长度，不补齐或截断到128；验证器不接收源Llama trace、D或oracle。

规模为224＋6×32＝416个正式源生成任务；D 384条、Model 256条，共640条去重序列证据，六类各256个视图共1536次引用。32条校准、KV donor、预检、重试及Model证明重算的额外执行另列。

## 注入与私有真值

复用旧decode step、Serving切换step、Input段起点与KV请求槽位；新层选择和扰动分别以本轮配置指纹派生独立种子。层范围改变后重新均匀选层；不复用旧分数、判定或抽样种子。

| 条件 | 本轮机制 |
|---|---|
| KV Cache | 仅full-attention层3/7/11/15/19/23均匀选层。干净Qwen donor替换一个历史K/V槽，只改当前最后输出行，历史行保持。若请求槽相同，按原固定循环找首个不同槽；不存在则错误。 |
| Serving r6 | 唯一切换后每步全部24层的末位MLP输出做FP32低6位nearest-even舍入，持续到结束。事件数为1＋24×(97−切换step)。 |
| Computation | 0–23层均匀选层，一步一层末位MLP施加归一化随机正负方向扰动，目标相对L2为1e-2。 |
| Token Selection | 一次greedy→最高分另一合法非special token，之后正常生成。 |
| Input Mismatch | 两个不同、不重叠的四-token段交换，起点1–28，保护首内容token并保持长度32。 |
| Model Mismatch | 请求级源模型切换到Llama，再提交Qwen有效重算证据。 |

Qwen KV重算必须保留query/gate拆分、Q/K norm、partial RoPE、同形状SDPA、sigmoid gate与o_proj。18个linear层的循环状态不纳入本次传统K/V槽替换。所有成功判据独立于检测结果；oracle保存实际状态变化、源请求/模型、donor生成、前后哈希和事件，不向验证器暴露。

## 校准、统计、执行与验收

先通过独立的实际checkpoint完整长度GPU→CPU预检：13块4+9、六类注入、六个KV层的恒等控制及单槽末行变化、linear/full两类Computation、全24层Serving、合法ID/EOS边界、首token保护与反向桥接隔离。小型24层混合CPU测试另验证真实重放、承诺篡改拒绝、共享引用和Wilson区间JSON往返。

正式执行：32个与正式输入独立的正常请求分别产生D/Model分数，以各自序列最大分数的32例最大值冻结阈值；缺失、非有限或执行错误阻止冻结。随后224个共享阴性、六类各32阳性、汇总、全量完成审计及中文对照报告。不以正式误报或攻击结果调阈值。数值主模式与严格计算输出哈希模式分别统计；GPU→CPU正常差异可造成严格拒绝。

成功且可判定阳性按DETECTED/PASSED计TP/FN，阴性计FP/TN；ERROR、不支持、失败及未知注入单列。各模式报告TPR/FPR/precision/F1、TPR/FPR的95% Wilson区间、注入成功率、可判定覆盖率和deployment recall。五类D条件共享同一阴性分母224，Model使用相同源响应的独立Model证据。

默认连续运行，每60秒记录和汇报。GPU不可用/OOM、可用显存不足768MiB、磁盘不足5GiB或连续三次相同执行错误停止进一步工作以便诊断。断点恢复核验代码、环境、模型、参考、词表、输入、配对时序和共享映射；未完成或失败版本归档，所有视图引用同一有效共享版本。

完成验收须覆盖640条证据、六个256样本视图、全部坐标和抽样重建、真实注入、去重成本及必保留索引0/64/128/192的完整张量。报告列出实际桥接长度、KV层覆盖、审计实际比例、源生成/证明/准备成本与v3对照，并保留分词差异及条件间相关性；固定seed、小模型、短输入不支持跨工作负载外推，不预设Qwen检出率。
